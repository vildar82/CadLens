# Design

## Context

Требуемое поведение описано в `specs/autocad-command/spec.md`; мотивация и границы первого среза — в `proposal.md`. Для ручной проверки на этой машине доступен Civil 3D 2026 на базе AutoCAD 2026. Отдельные установки AutoCAD 2025 и 2026 не обнаружены.

AutoCAD 2025 и 2026 первоначально работали на .NET 8, но обновления 2025.1.4 и 2026.1.2 переводят хост на .NET 10. По [таблице совместимости Autodesk](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-Customization/files/GUID-D54B0935-1638-4F97-8B37-1EC3635A1E71.htm) и [объявлению для разработчиков](https://blog.autodesk.io/autodesk-desktop-products-2025-2026-net-10-updates/) плагины .NET 8 обычно продолжают работать после обновления, но это требует проверки в целевом хосте.

## Goals / Non-Goals

**Goals:**

- Получить один небольшой проект библиотеки, который можно собрать и вручную загрузить в AutoCAD 2025/2026.
- Сделать результат запуска команды видимым в командной строке без изменения базы чертежа.
- Отделить успешную сборку от проверки загрузки и исполнения внутри AutoCAD.

**Non-Goals:**

- Создавать основу для DI, окон, ленты или жизненного цикла будущих линз до появления соответствующего поведения.
- Настраивать постоянную загрузку плагина или установку на другие машины.

## Decisions

### Один проект с минимальной точкой входа

Создать SDK-style библиотеку `src/AutoCAD/CadLens.AutoCAD/CadLens.AutoCAD.csproj` с целевой платформой `net8.0-windows` и добавить проект в `CadLens.slnx`. Общие свойства сборки и версии пакетов хранить в корневом `Directory.Build.props`. Команду зарегистрировать атрибутом `CommandMethod("CADLENS")` в классе команды. Класс и метод пометить `UsedImplicitly`: AutoCAD вызывает их через регистрацию, поэтому Rider не видит обычных вызовов из кода. Обычный документный контекст достаточен: команда запускается при открытом DWG и не требует фонового доступа к другим документам. Вместо собственного механизма регистрации или RxBim-команд выбран штатный API AutoCAD, чтобы первый срез не зависел от инфраструктуры, которая ему пока не нужна. [Документация Autodesk по командам](https://help.autodesk.com/cloudhelp/2015/PLK/AutoCAD-NET/files/GUID-F77E8FE0-8034-4704-93BD-F717608F8223.htm).

### Вывод через редактор без доступа к DWG

Метод команды берёт редактор активного документа и вызывает `Editor.WriteMessage` с приветствием, содержащим `CAD Lens`. Он не открывает транзакции, не получает объекты базы и не вызывает команды AutoCAD для изменения чертежа. Флаг `NoUndoMarker` уместен для команды без изменения базы. Альтернатива — отдельный сервис вывода — добавила бы слой без второго потребителя. [Описание `Editor.WriteMessage`](https://help.autodesk.com/cloudhelp/2024/ENU/OARX-ManagedRefGuide/files/OARX-ManagedRefGuide-Autodesk_AutoCAD_EditorInput_Editor_WriteMessage_string_params_object__.html).

### NuGet-пакет AutoCAD и совместимость версий

Добавить в корневой `Directory.Build.props` ссылки на [Autodesk `AutoCAD.NET` версии 25.0.1](https://www.nuget.org/packages/AutoCAD.NET/25.0.1) и `JetBrains.Annotations` 2025.2.4. `JetBrains.Annotations` подключается всем проектам, `AutoCAD.NET` — только при `UseAutocad=true`. Флаг задать в `.csproj`: при оценке `ItemGroup` свойства проекта уже доступны для условия в корневом props. Все версии зависимостей первого среза видны в одном файле. Пакет AutoCAD содержит API AutoCAD 2025 для .NET 8 и подтягивает нужные зависимости через NuGet. Не задавать пути к SDK или установленному AutoCAD и не добавлять прямые ссылки на DLL. Пакетные сборки нужны при компиляции; при загрузке плагина API предоставляет AutoCAD, поэтому runtime-ресурсы пакета исключить из публикации и проверить, что DLL AutoCAD не попали в выходной каталог плагина. По [матрице Autodesk](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-Customization/files/GUID-A6C680F2-DE2E-418A-A182-E4884073338A.htm) API AutoCAD 2025 поддерживается AutoCAD 2026. Альтернатива — пакет `AutoCAD.NET` 25.1.x для AutoCAD 2026 — привязала бы сборку к более новому API без необходимости для команды приветствия.

### Ручная загрузка и проверка

Первый способ загрузки — `NETLOAD` собранной DLL из доверенного каталога, затем вызов `CADLENS` при открытом DWG. Для завершения первого среза достаточно проверки в доступном Civil 3D 2026: приветствие, завершение без дополнительных запросов и неизменность состояния DWG. Совместимость с отдельными установками AutoCAD 2025/2026 и хостами после обновления до .NET 10 остаётся непроверенной до появления этих хостов. Сборка и валидация OpenSpec подтверждают только статическую часть. [Порядок загрузки Autodesk](https://help.autodesk.com/cloudhelp/2026/KOR/OARX-DevGuide-Managed/files/GUID-577EDC34-0A10-4D63-BED4-ECA4570355A3.htm).

## Risks / Trade-offs

- [Пакет `AutoCAD.NET` недоступен при восстановлении или нет отдельного AutoCAD для проверки] → фиксированную версию пакета восстанавливать из NuGet; сбой восстановления считать блокером сборки, отсутствие хоста — непроверенной совместимостью, а не успешным тестом.
- [Обновление хоста до .NET 10 может выявить несовместимость DLL] → проверить загрузку и команду в обновлённом AutoCAD; при подтверждённом сбое добавить отдельную сборку под `net10.0-windows`, не меняя контракт команды.
- [AutoCAD отклоняет `NETLOAD` из-за `SECURELOAD`/`TRUSTEDPATHS`] → загружать DLL из доверенного каталога, не отключая защиту AutoCAD.

## Migration Plan

Постоянной установки и миграции DWG нет. Для пробного запуска собрать DLL, загрузить её через `NETLOAD` и выполнить команду. Для отката убрать DLL из пробного каталога и перезапустить AutoCAD: загруженную .NET-сборку нельзя выгрузить из текущего процесса обычной командой.
